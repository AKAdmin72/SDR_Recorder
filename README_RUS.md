# SDR Monitor

Приложение для мониторинга радиоэфира в реальном времени на HackRF или
RTL-SDR: слежение за выбранным диапазоном частот, детекция передач
относительно адаптивного шумового пола, демодуляция (AM или FM) и
сохранение каждой передачи в WAV-файл — с живым GUI (спектр + таблицы) или
в headless-режиме для записи без присмотра.

[Read in English / английская версия](README.md)

## Возможности

- **Живой спектр**: график max-hold, шумовой пол, пороги открытия/закрытия
  детекции и исключённые (blacklisted) диапазоны частот — всё на одном графике.
- **Автоматическая детекция**: адаптивный шумовой пол по каждому бину
  (скользящий перцентиль) с гистерезисом (раздельные пороги открытия и
  закрытия) и подтверждением по нескольким кадрам подряд — отсекает
  случайные шумовые выбросы.
- **AM и FM демодуляция**, выбирается в конфиге.
- **Автоматическая запись** каждой обнаруженной передачи в WAV с фильтром
  минимальной длительности и post-roll — короткие шумовые всплески не
  создают мусорных файлов, а реальные передачи не обрезаются резко.
- **Несколько именованных config-профилей** (`config/*.toml`) — например,
  по одному на комбинацию диапазон/устройство/модуляция — с интерактивным
  выбором при запуске, если файлов несколько.
- **GUI-редактор конфига** (`sdr-monitor-config`, либо кнопка "Config..." в
  главном окне) — структурированная форма на каждое поле конфига, включая
  полное добавление/удаление исключённых диапазонов частот. Правки
  применяются точечными патчами поверх текста TOML-файла, поэтому все
  существующие комментарии и форматирование сохраняются.
- **Поддержка HackRF и RTL-SDR** через общий интерфейс устройства.

## Архитектура

Один и тот же потоковый конвейер и в GUI, и в headless-режиме:

```
SDR (HackRF / RTL-SDR)
  -> IQStreamReader        (асинхронный приём по USB, очередь блоков IQ)
  -> FFTProcessor           (оконное FFT, усреднение, DC-notch)
  -> NoiseFloorEstimator    (скользящий перцентиль по каждому бину)
  -> SignalDetector         (гистерезис + подтверждение по кадрам -> треки)
  -> RecordingManager
       -> ChannelExtractor  (перенос на 0 Гц + децимация до канала детекции)
       -> Demodulator       (огибающая AM или квадратурный дискриминатор FM)
       -> AudioFilter       (полосовой фильтр речевого диапазона)
       -> AudioResampler    (децимация до частоты дискретизации записи)
       -> WaveRecorder      (буферизуется в памяти, пишется на диск после
                              достижения минимальной длительности)
```

Точки входа GUI и headless (`run_gui`/`run_headless` в `app.py`) строят
абсолютно один и тот же конвейер; GUI дополнительно управляет окном
`tkinter` (`MonitorWindow`), которое вычерпывает очередь по таймеру, а не в
отдельном потоке — Tcl/Tk требует однопоточного доступа.

## Требования

- Python >= 3.11
- Приёмник HackRF One или RTL-SDR (на базе RTL2832U)
- Родная драйверная библиотека производителя:
  - HackRF: `libhackrf.dll` (по умолчанию ожидается по пути
    `C:\HackRF\bin\libhackrf.dll`, переопределяется переменной окружения
    `HACKRF_DLL_PATH`)
  - RTL-SDR: `rtlsdr.dll` (по умолчанию `C:\RTLSDR\bin\rtlsdr.dll`,
    переопределяется переменной окружения `RTLSDR_DLL_PATH`)

  Обе библиотеки загружаются напрямую через `ctypes` — Python-пакеты
  `pyhackrf`/`pyrtlsdr` не требуются, нужна только сама нативная DLL (и её
  собственные зависимости, `libusb-1.0.dll`/`libwinpthread-1.dll`, рядом с ней).

## Установка

```
pip install -e .
```

Устанавливает консольные команды `sdr-monitor` и `sdr-monitor-config` (см.
`pyproject.toml`).

Для запуска тестов:

```
pip install -e ".[dev]"
```

## Запуск

С интерактивным выбором конфига (если в `config/` больше одного `*.toml`)
или с явным указанием:

```
sdr-monitor
sdr-monitor --config config/rtl_126_3_am.toml
```

Headless-режим (без GUI — для фоновой записи без присмотра):

```
sdr-monitor --headless
sdr-monitor --headless --duration 3600   # остановка через 1 час
```

Редактор конфига (отдельное GUI-окно, либо кнопка "Config..." в главном окне):

```
sdr-monitor-config
sdr-monitor-config --config config/app_config.toml
```

## Конфигурация

Все параметры выполнения — выбор устройства, настройка частоты, усиление,
размер FFT, пороги детекции, режим демодуляции, поведение записи — задаются
в TOML-файле в каталоге `config/`. `config/app_config.toml` — конфиг по
умолчанию; остальные файлы — именованные профили под конкретные
диапазоны/устройства/режимы, например:

- `config/rtl_126_3_am.toml` — RTL-SDR, 126.3 МГц, AM (авиадиапазон)
- `config/rtl_155_1_fm.toml` — RTL-SDR, 155.1 МГц, FM

Секции `[radio.hackrf]` и `[radio.rtlsdr]` могут присутствовать в одном
файле одновременно — реально используется только та, что совпадает с
`[sdr].type`, поэтому переключение приёмника не требует удаления другой
секции. Диапазоны частот, которые нужно полностью исключить из детекции
(например, паразитные артефакты самого приёмника), задаются через
`[[detection.blacklisted_ranges]]`.

Каждое поле в конфигах снабжено комментарием с описанием, допустимым
диапазоном и — где это уместно — обоснованием текущего значения.

## Тестирование

```
pytest
```

Набор тестов полностью самодостаточен (реальное железо не требуется) —
классы устройств тестируются через общий интерфейс `SdrDevice` и фабрику,
что позволяет проверять остальной конвейер на синтетических IQ-данных.

## Записи

Обнаруженные передачи сохраняются в WAV-файлы в каталоге `recordings/`
(путь настраивается через `audio.recordings_dir`), по одному файлу на
передачу, с именем по UTC-времени и центральной частоте.
